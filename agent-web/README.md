# StreamDoctor Agent Web

独立的运行诊断 Agent 工作台。它把现有电梯监测平台作为被检测项目，页面本身不依赖原业务 Vue 或 Java 服务。

## 本地开发

```powershell
npm install
npm run dev
```

页面默认在 `http://127.0.0.1:4173`，通过 Vite 代理访问 `http://127.0.0.1:8099/api/agent`。先启动 Python Agent：

```powershell
cd ..\agent-service
.venv\Scripts\python.exe -m uvicorn streamdoctor.api:app --host 127.0.0.1 --port 8099
```

工作台包含项目和会话、受控工具执行、SSE 时间线、运行证据、拓扑面板、指标面板以及长期记忆确认。左侧“模板库”提供五套内置链路，也可以创建和持续修改自定义模板。新建项目时选择模板，进入“资源与链路”后可修改服务器、服务、节点、关系和扩展配置；每次发布形成新版本，历史版本通过“恢复”复制成新的当前版本。

右侧“分析”页签展示本轮候选假设及其支持、未支持或未知状态，并把模型服务、Flink 反压和 Kafka 积压组织为可点击证据的观测时间线。诊断生成的 Kafka 积压 Artifact 在“指标”页签显示处理前后的变化；点击时间线信号可以回到对应原始证据。

首页操作按运行生命周期划分：运行巡检用于建立健康基线，故障诊断用于根据现象定位根因，处置与恢复用于核对处置清单并重新采样验证。基础版本采用人工确认处置，未注册可写操作时不会直接重启或修改 Kafka、Flink 和模型服务；失败或取消的 Agent Run 使用“继续任务”重新执行，它与业务链路的恢复验证是两个概念。

每个项目维护独立的会话列表。新建会话时填写标题，会话支持重命名、归档、恢复和永久删除，并显示消息数量。永久删除会同时清理该会话的消息、运行事件、工具调用、证据和 Artifact；运行中的会话必须先停止任务。

规格编辑器也支持从自然语言描述生成草稿，以及导入 `.txt`、`.md`、`.json`、`.yaml`、`.yml` 文本文档。导入结果必须在编辑器中核对并发布，系统不会因为文档内容自动覆盖当前项目配置。

## 容器部署

`Dockerfile` 构建静态网页，`nginx.conf` 将 `/api/agent` 反向代理到同一 Compose 网络中的 `agent:8099`。部署时把 Agent 与网页加入同一个 Docker 网络，并只对外暴露网页端口。
